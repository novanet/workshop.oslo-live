Prerequisites

Dette må være på plass før du begynner å bygge agenten. Du trenger ikke ha deployet noe på forhånd; kurset tar deg gjennom resten.

Forberedelse15–30 minutter hvis du bruker devcontainer.
MiljøCodespace eller lokal devcontainer er anbefalt.
Første målFå en grønn miljøsjekk før Lab 1.

Dette trenger du

Kryss av listen før kursdagen, eller bruk den som startpunkt når du åpner mini-nils.zip.

  • En GitHub-konto som kan opprette et privat repository.
  • Tilgang til novanet/workshop.oslo-live gjennom et personlig fine-grained GitHub-token du lager for akkurat dette repoet.
  • En laptop der du kan åpne Codespaces eller kjøre en devcontainer, alternativt tilgang til en ferdig kursmaskin.
  • En kopi av mini-nils.zip, lastet ned og pakket ut lokalt.
  • En nettleser som kan logge inn på GitHub og Azure med kurskontoene dine.

Velg arbeidsmiljø

Devcontainer eller Codespace

Anbefalt. Starter-kitet har et ferdig miljø med .NET 10, GitHub CLI, Azure CLI, Node.js og Claude Code. Du slipper å feilsøke lokale versjoner.

Lokalt miljø

Installer .NET 10 SDK, Git, gh, Azure CLI, Node.js og Claude Code selv. Lab 2 trenger også curl og jq. jq leser JSON-filer fra Azure og plukker ut for eksempel mottaks-URL-en.

Hvis noe er blokkert

Si fra før Lab 1. Codespaces eller en kursmaskin er fallback, slik at miljøoppsett ikke spiser tiden til oppgaven.

KEDA i Lab 2KEDA (Kubernetes Event-driven Autoscaling) følger med på Storage Queue og starter Azure-jobben når det ligger en melding der. Det gjør at workeren kan skalere til null når køen er tom i stedet for å kjøre hele tiden. Lab 2 forklarer hvordan polling-intervallet påvirker ventetiden.

Lag ditt GitHub-token

Tokenet brukes av workeren mot øvingsrepoet. Det er separat fra gh auth login, som du bruker med din egen GitHub-konto for å opprette agentrepoet.

1

Åpne fine-grained tokens

Gå til GitHub → New fine-grained token. Velg bare novanet/workshop.oslo-live under repository access.

2

Gi minst mulig tilgang

Velg Contents, Issues og Pull requests med read/write, og Metadata med read. SSO er bare relevant hvis GitHub faktisk viser en SSO-godkjenning; det er normalt å ikke se en slik knapp.

3

Lagre verdien lokalt

cp .env.example .env
GH_TOKEN=github_pat_...

GitHub viser tokenverdien bare én gang. Legg den som repository secret med navnet GH_TOKEN; ikke legg den i kode, issue, PR eller skjermbilde. Hvis Azure-workeren logger addComment eller replaceActorsForAssignable, kontroller først at tokenet gjelder riktig repo, deretter Issues write og brukerens skrivetilgang.

FerdigDu er klar for Lab 1 når verktøyene svarer, løsningen bygger grønt og kurslederen har gitt deg ANTHROPIC_API_KEY. Test GitHub-tokenet uten API-kall med dotnet run --project src/Worker -- --issue 1 --repo novanet/workshop.oslo-live --dry-run. Ingen lokal issue-kjøring skal reservere, kommentere eller opprette PR; det skjer først fra Azure i Lab 2.

Hvis betalingen eller nøkkelen stopper deg

Du skal normalt ikke kjøpe API-kreditt selv for kurset. Claude.ai-abonnement og Anthropic API-betaling er separate.

Anthropic workspace-feilDen nyeste starter-koden setter kursets workspace-ID automatisk hvis .env mangler variabelen. Hvis feilen fortsatt vises, hent den nyeste mini-nils.zip og kontroller at oppstartloggen sier at Anthropic workspace-ID er satt. API-nøkkelen må komme fra kurslederen og ha tilgang til workspace-et. Ikke send API-nøkkel i chat. --dry-run kan fortsatt brukes uten nøkkel.

Ikke nødvendig før start

  • Du trenger ikke opprette Azure-ressurser selv før kurset.
  • Du trenger ikke lage en egen webhook før kurslederen har gitt deg URL og hemmelighet.
  • Du trenger ikke forstå hele workeren før Lab 1; du implementerer RunStages steg for steg.
