Prerequisites

Dette må være på plass før du begynner å bygge agenten. Du trenger ikke ha deployet noe på forhånd, og du trenger ingen Azure-innlogging. Deployen går fra GitHub Actions.

Forberedelse15–30 minutter.
MiljøPowerShell 7 lokalt. Devcontainer eller Codespace er fallback.
Første målFå en grønn miljøsjekk før Lab 1.

Dette trenger du

Kryss av listen før kursdagen, eller bruk den som startpunkt når du åpner mini-nils.zip.

  • En GitHub-konto som kan opprette et privat repository.
  • Tilgang til novanet/workshop.oslo-live gjennom et klassisk GitHub-token med bare public_repo. Kurslederen legger deg til som collaborator med Write først; godta invitasjonen på e-post eller på repoet.
  • En laptop med PowerShell 7 (pwsh), .NET 10 SDK, Git, gh og Python 3.
  • En kopi av mini-nils.zip, lastet ned og pakket ut lokalt.
  • En nettleser der du er logget inn på GitHub.

Velg arbeidsmiljø

Lokalt med pwsh

Hovedsporet. Installer PowerShell 7, .NET 10 SDK, Git, gh og Python 3. Alle kommandoene i labbene er skrevet for pwsh. Du trenger ikke az, jq, Docker, Node.js eller Claude Code lokalt. Dry-run kaller ikke Claude, og Claude Code ligger i worker-imaget i Azure.

Devcontainer eller Codespace

Fallback hvis du ikke får installert verktøyene. Starter-kitet har et ferdig miljø med .NET 10, gh og pwsh. Start pwsh i terminalen, så virker kommandoene i labbene likt.

Hvis noe er blokkert

Si fra før Lab 1. Codespaces eller en kursmaskin er fallback, slik at miljøoppsett ikke spiser tiden til oppgaven.

KEDA i Lab 2KEDA (Kubernetes Event-driven Autoscaling) følger med på Storage Queue og starter Azure-jobben når det ligger en melding der. Det gjør at workeren kan skalere til null når køen er tom i stedet for å kjøre hele tiden. Lab 2 forklarer hvordan polling-intervallet påvirker ventetiden.

Kurs-tokenet med public_repoGH_TOKEN lager du selv som et klassisk token med bare public_repo på GitHub. Vær klar over hva det gir: public_repo når alle offentlige repoer du kan skrive til, ikke bare Oslo Live. Derfor skal det ha kort utløp, og workeren er låst til TARGET_REPO (novanet/workshop.oslo-live) og avviser andre repoer. Du må ha godtatt collaborator-invitasjonen, ellers får tokenet ikke skrive. Lag ditt GitHub-token

Tokenet brukes av workeren mot øvingsrepoet. Det er separat fra gh auth login, som du bruker med din egen GitHub-konto for å opprette agentrepoet.

1

Åpne klassiske tokens

Gå til GitHub → New personal access token (classic). Lenken fyller inn navn og scope for deg. Fine-grained funker ikke for collaborators utenfor Novanet-orgen.

2

Gi minst mulig tilgang

Kryss bare av public_repo. Ikke velg hele repo, da får tokenet tilgang til alle private repoer du har. Velg kort utløp, for eksempel 7 dager.

3

Lagre verdien lokalt

Copy-Item .env.example .env

Åpne .env og fyll inn:

GH_TOKEN=ghp_...
AGENT_NAME=kari

GitHub viser tokenverdien bare én gang. Mot slutten av Lab 1 legger du den også inn som repository secret GH_TOKEN. Ikke legg den i kode, issue, PR eller skjermbilde. Hvis Azure-workeren logger addComment eller replaceActorsForAssignable, sjekk først at du har godtatt collaborator-invitasjonen, deretter at tokenet har public_repo.

Miljøsjekk

Kjør dette i pwsh fra mappen der du pakket ut starter-kitet. Versjonsnumrene kan være nyere, men kommandoene skal svare uten feil.

$PSVersionTable.PSVersion
dotnet --version
git --version
gh --version
gh auth status
python --version
dotnet build
FerdigDu er klar for Lab 1 når verktøyene svarer, gh auth status viser at du er logget inn, og løsningen bygger grønt. Test GitHub-tokenet uten API-kall med dotnet run --project src/Worker -- --issue 1 --repo novanet/workshop.oslo-live --dry-run. Ingen lokal issue-kjøring skal reservere, kommentere eller opprette PR. Det skjer først fra Azure i Lab 2.

Hvis betalingen eller nøkkelen stopper deg

Du skal ikke kjøpe API-kreditt selv. Claude.ai-abonnement og Anthropic API-betaling er separate.

Anthropic-nøkkelenKurset har én felles Anthropic-nøkkel med ett felles kostnadstak. Den legges bare som repository secret og brukes av Azure-workeren. Du trenger den ikke lokalt, --dry-run virker uten. Ikke send nøkkelen i chat. Feiler Azure-jobben på nøkkel eller workspace, si fra til kurslederen.

Ikke nødvendig før start

  • Du trenger ingen Azure-konto, Azure-innlogging eller az. Deployen kjører fra GitHub Actions.
  • Du trenger ikke opprette Azure-ressurser selv.
  • Du trenger ikke lage webhooken. Kurslederen kobler den til i lunsjen.
  • Du trenger ikke forstå hele workeren før Lab 1; du implementerer RunStages steg for steg.
