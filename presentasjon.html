Formålet med kurset

Målet med dagen

Ved slutten av dagen

  • Du har en agent du eier. Koden, instruksjonene og oppsettet ligger i ditt repo.
  • Agenten din har opprettet en PR. Agenten har behandlet en issue og levert den til review.
  • Du kan endre den. Modell, verktøy og regler ligger i repoet ditt.

Dette øver vi på

  • Fra issue til PR. Vi følger oppgaven fra GitHub til ferdig forslag.
  • Kode rundt LLMen. Webhook, git, bygg, test og PR ligger i workeren.
  • Hvordan forbedre agenten. Du endrer én ting og ser hva det gjør med resultatet.

Deployment · tre steder

Hvor ligger hva?

Fra issue til worker

Slik starter en jobb

01 Issue får etikett GitHub sender en webhook.
02 Receiver tar imot Signaturen sjekkes, og meldingen legges i kø.
03 KEDA ser køen KEDA starter en worker når det finnes arbeid.
04 Worker kjører Agenten tildeler, kommenterer og oppretter PR.
Poenget: Når webhooken er koblet til, trenger ikke laptopen din å være med.

Pipeline · fem faser

Fem steg fra issue til PR

1Research Finn relevant kode og lag en plan. claude-opus-5
2Plan review Sjekk planen før vi skriver kode. claude-haiku-4.5
3Implement Gjør endringen i repoet. claude-fable-5
4Self-review Se over diffen og rett feil. claude-opus-5
5Build & deliver Bygg, test, push og opprett PR. kode, ikke LLM
Husk: Mini-Nils bruker Claude Code. Bygg, test og PR skjer i worker-koden, ikke som et valg modellen tar.

09:00–12:15 · sjekkpunkt 1

Lab 1: bygg pipelinen lokalt

Start med å koble sammen delene på maskinen din. GitHub-klienten og modellkallet følger med.

1Gjør klartmini-nils.zip, eget repo, .env og en dry-run.
2Implementer flytenKoble sammen RunStages: kontekst, modellsteg og verifisering.
3Sjekk oppsettetBygg og kjør dry-run. Lokal kjøring skal ikke skrive til GitHub.
Sjekkpunkt 1: Din egen RunStages bygger grønt, dry-run er ren, og du kan forklare hvordan workeren senere skal reservere issue, kommentere og åpne PR fra Azure. Direkte issue-kjøring er skrivebeskyttet.
Redningsnett: ./sjekkpunkt.sh lab1 tar vare på forsøket ditt og legger inn en fungerende baseline.

13:00–14:00 · sjekkpunkt 2

Lab 2: deploy agenten til Azure

Nå skal agenten starte fra GitHub og levere PR fra Azure uten at laptopen din er med.

1DeployGitHub Actions bruker repository secrets og oppretter Receiver, kø, jobb og logger.
2Koble webhookKurslederen kobler Oslo Live til mottaket og etiketten din.
3Følg jobbenSe jobben starte, les loggen og test at en feil hemmelighet gir 401.
Sjekkpunkt 2: En issue merket i GitHub gir en pull request fra Azure. Vis også en liten Bicep-endring som er deployet på nytt.

14:15–15:00 · sjekkpunkt 3

Lab 3: velg en forbedring

Velg én ting du vil forbedre. Kjør samme type oppgave før og etter, og vis forskjellen.

KvalitetsporterLegg inn kontroller mellom stegene, og la rødt bygg stoppe leveransen.
Skills og hukommelseSe hva agenten tar med seg til neste kjøring.
SikkerhetBegrens verktøyene, og test en instruksjon som kommer fra en issue.
MonitoreringVis status, PR, tid og forbruk på en enkel side.
Sjekkpunkt 3: Vis forskjellen før og etter, eller vis monitoreringssiden og forklar hvordan statusen beregnes. Du kan også velge stopp og grenser, lære av feilene eller bestemme når agenten skal få gå videre.

Oppsummering og demo

I demoen

  • Vis oppgaven og PR-en. Vis kort hva agenten endret.
  • Vis hva du endret. Det kan være prompt, modell, verktøy eller en kontroll.
  • Fortell hva du fant ut. Hva ble bedre, og hva ville du jobbet videre med?

Dette tar du med deg

  • Reglene rundt modellen er en del av agenten.
