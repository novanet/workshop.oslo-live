Sjekkpunkt 1 · lokalt

Lab 1: Monter agenten

Implementer forbindelsen fra GitHub-issue til pull request i Pipeline.cs. Du får ferdige komponenter og en tekstlig oppskrift, men skriver selv orkestreringen.

MålEn agent som lager en reviewbar PR.
ArbeidsstedDitt eget repo og din lokale devcontainer.
Ferdig nårDin egen RunStages har åpnet en PR.

Før du begynner

Ha dette klart før du begynner:

  • Et eget privat repo for agenten din.
  • Skrivetilgang til novanet/workshop.oslo-live via et fine-grained GitHub-token med Contents, Issues og Pull requests read/write, samt Metadata read-only. Autoriser tokenet for Novanet SSO hvis GitHub ber om det.
  • En kopi av mini-nils.zip, pakket ut i mappen der du skal jobbe.
  • En devcontainer eller Codespace med .NET 10, gh og Claude Code.

Agenten endrer ikke sitt eget repo. Den kloner øvingsrepoet, lager en branch der og åpner pull requesten der.

Lag agentrepoet

git init -b main
git add -A
git commit -m "Start fra delene til Mini-Nils"
gh repo create mini-kari --private --source . --push

Bytt kari med navnet ditt.

Fyll inn miljøet

cp .env.example .env
AGENT_NAME=Mini-Kari
GH_TOKEN=github_pat_...
ANTHROPIC_API_KEY=sk-ant-...

Tokenet trenger Contents, Issues og Pull requests med read/write på øvingsrepoet. Feilen Resource not accessible ... (addComment) betyr vanligvis manglende Issues write eller SSO-godkjenning. Hvis workeren sier Mangler ANTHROPIC_API_KEY, må du be kurslederen om Claude-nøkkelen og legge den i .env. --dry-run kan kjøres uten Anthropic-nøkkel.

Sjekk verktøyene

dotnet --version
gh --version
claude --version
dotnet build

Bruk devcontainer eller Codespaces hvis noe mangler. På Windows kan du installere Claude Code med npm install -g @anthropic-ai/claude-code.

Test uten å starte agenten

Vil du bare sjekke at issuen er tilgjengelig og ikke allerede reservert, uten å klone repoet eller bruke modellkall?

dotnet run --project src/Worker -- `
  --issue 1 `
  --repo novanet/workshop.oslo-live `
  --dry-run

--dry-run reserverer ikke issuen og stopper før clone, issue-kommentar, Claude Code, commit og PR. Kombinerer du det med --skip-reservation, hoppes reservasjonssjekken over og workeren stopper rett etter at issuen er hentet. Dry-run krever ikke ANTHROPIC_API_KEY og kan bare brukes med --issue og --repo, ikke kømodus.

Start med et kompilérbart skjelett

Scriptet legger inn en skjelettfil med den ytterste Run-metoden og alle hjelpeklassene du trenger. RunStages er din oppgave.

python setup-lab1.py
dotnet build

Det som stod der fra før lagres i .kurs/Pipeline.forsok.cs. Ikke åpne sjekkpunktet ennå; det er den ferdige løsningen som skal brukes hvis du faller av.

Oppskriften for RunStages

Implementer ett steg om gangen. Kjør dotnet build etter hvert steg. Oppskriften beskriver kontrakten, men ikke C#-løsningen.

1

Reservasjon · før modellkallet

Reserver oppgaven

Med --skip-reservation logger du at reservasjonen hoppes over. Ellers kaller du Reservation.IsBusy(task, AgentName). Ved årsak kommenterer du på issuen og returnerer 0; ellers kaller du Reservation.Claim(task).

2

Arbeidsområde · ren start

Klon repoet og lag branch

Kall Repository.Clone(task.Repo, workspace), lag task.BranchName med CreateBranch, logg repo.Path og kommenter StartMarker(task). Modellen skal aldri jobbe direkte på main.

3

Kontekst · eksplisitt input

Bygg systemprompt og kontekst

Kall InstallSkills(), ReadMemory() og BuildSystemPrompt(memory). Start previousOutput som en tom streng. Regler, konvensjoner og hukommelse skal være lesbar input.

4

Modellsteg · styrt tilgang

Kjør config.Stages

For hvert steg velger du stage.Model eller config.Model, bygger prompt med BuildPrompt, kaller ClaudeRunner.Run, legger resultatet i runs og logger LogUsage. Ved feil kommenterer du, bruker EndMarker og returnerer 1.

5

Diff-port · ingen tom PR

Krev en faktisk endring

Kall repo.HasChanges(). Ved tom diff kommenterer du siste svar, husker utfallet med Remember, legger ved forbruk og returnerer 0.

6

Verifisering · utenfor modellen

Kjør bygg og test som en port

Kall Verify(repo.Path). Når verifiseringen feiler og StopOnVerifyFailure er sann, kommenterer du verifyLog, husker utfallet og returnerer 2 uten PR.

7

Leveranse · reviewbar PR

Commit, push og opprett PR

Kall CommitAndPush, bygg PR-teksten med PrBody og kall CreatePullRequest. Bruk utkast når verifiseringen er rød, og aktiver auto-merge bare når den er grønn. Skriv sammendrag og husk utfallet.

Kjør og nå sjekkpunktet

dotnet run --project src/Worker -- `
  --issue 1 `
  --repo novanet/workshop.oslo-live `
  --skip-reservation

Følg loggen: reservasjonen kontrolleres eller hoppes over, repoet klones, modellstegene kjører, bygg/test kjøres og PR-adressen skrives ut.

Sjekkpunkt 1Din egen implementasjon av RunStages har åpnet en PR, bygget er grønt, og du kan forklare hva som er deterministisk kode og hvor modellen brukes.

Hvis du faller av

Forsøket ditt blir tatt vare på før den ferdige løsningen kopieres inn:

./sjekkpunkt.sh lab1
dotnet build

I PowerShell kan du se forskjellen slik:

code --diff .kurs\Pipeline.forsok.cs src\Worker\Pipeline.cs
RedningsnettLes den ferdige pipelinen etterpå og finn ut hvilket steg du manglet før du går videre til Lab 2.

Hvis man blir tidlig ferdig

  • Flytt en kontroll og begrunn hvorfor den fortsatt er deterministisk.
  • Endre hva som skjer når verifisering feiler.
  • Logg en ekstra måling i PR-rapporten.
  • Gi et modellsteg mindre verktøytilgang.

Dokumenter hva som ble bedre, hva som ble dårligere og hvilken måling som viser forskjellen.
