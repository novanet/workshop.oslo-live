Lab 1: Monter agenten

Bygg forbindelsen fra GitHub-issue til pull request ved å montere ferdige deler i Pipeline.cs. Du skal ikke skrive GitHub-klienten eller modellintegrasjonen fra bunnen.

MålEn agent som lager en reviewbar PR.
ArbeidsstedDitt eget repo og din lokale devcontainer.
Ferdig nårIssue 1 har gitt deg en pull request.

Før du begynner

Ha dette klart før du begynner:

  • Et eget privat repo for agenten din.
  • Skrivetilgang til novanet/workshop.oslo-live via et GitHub-token med Contents, Issues og Pull requests med read/write.
  • En kopi av mini-nils.zip, pakket ut i mappen der du skal jobbe.
  • En devcontainer eller Codespace med .NET 10, gh og Claude Code.

Agenten endrer ikke sitt eget repo. Den kloner øvingsrepoet, lager en branch der og åpner pull requesten der.

Lag agentrepoet

git init -b main
git add -A
git commit -m "Start fra delene til Mini-Nils"
gh repo create mini-kari --private --source . --push

Bytt kari med navnet ditt.

Fyll inn miljøet

cp .env.example .env
AGENT_NAME=Mini-Kari
GH_TOKEN=github_pat_...
ANTHROPIC_API_KEY=sk-ant-...

Tokenet trenger Contents, Issues og Pull requests med read/write på øvingsrepoet.

Sjekk verktøyene

dotnet --version
gh --version
claude --version
dotnet build

Bruk devcontainer eller Codespaces hvis noe mangler.

Monter i sju trinn

Åpne src/Worker/Pipeline.cs. Erstatt én nummerert kommentar om gangen, og kjør dotnet build etter hvert trinn. Ikke gå videre med rødt bygg.

1

Reservasjon · før modellkallet

Hindre at to agenter tar samme issue

Bytt ut kommentaren om reservasjon med Reservasjon.Opptatt og Reservasjon.Ta. Når --force er satt, skal sjekken hoppes over.

if (!force)
{
    var grunn = await Reservasjon.Opptatt(task, AgentNavn);
    if (grunn is not null) return 0;
    await Reservasjon.Ta(task);
}

Sjekk: dotnet build. Reservasjon er deterministisk kode, ikke en instruksjon til modellen.

2

Arbeidsområde · ren start

Klon og opprett branch

Bruk Repository.Clone og CreateBranch. Modellen skal arbeide i en fersk checkout fra oppdatert main, aldri i agentrepoet.

var repo = await Repository.Clone(task.Repo, workspace);
await repo.CreateBranch(task.BranchName);
await Kommenter(repo, task, Startlinje(task));

Sjekk: dotnet build. Agentnavnet inngår i branchnavnet, slik at flere kan jobbe parallelt.

3

Kontekst · eksplisitt input

Installer skills og bygg systemprompten

Kall InstallSkills, les hukommelsen og bygg prompten med BuildSystemPrompt. Hold konteksten lesbar og versjonert.

InstallSkills();
var minne = await LesHukommelse();
var systemPrompt = BuildSystemPrompt(minne);
var previousOutput = "";

Sjekk: dotnet build.

4

Modellsteg · styrt tilgang

Kjør hver stage fra agent/stages.json

For hver stage velger du modell, bygger prompten og kaller ClaudeRunner.Run. Logg tokens og stopp hvis et steg feiler.

foreach (var stage in config.Stages)
{
    var result = await ClaudeRunner.Run(
        stage, stage.Model ?? config.Model,
        BuildPrompt(stage, task, previousOutput),
        systemPrompt, repo.Path);
    runs.Add(new StageRun(stage.Name, stage.Model, result));
    if (!result.Ok) return 1;
    previousOutput = result.Text;
}

Sjekk: dotnet build. Verktøylisten og maks antall turer kommer fra konfigurasjonen.

5

Diff-port · ingen tom PR

Krev at agenten faktisk endret noe

Et godt svar uten kode er ikke en leveranse. Bruk repo.HasChanges(); kommenter og husk resultatet hvis diffen er tom.

if (!await repo.HasChanges())
{
    await Kommenter(repo, task, "Ingen kodeendring.");
    await Husk(task, "ingen kodeendring", runs);
    return 0;
}

Sjekk: dotnet build.

6

Verifisering · utenfor modellen

Kjør bygg og test som en deterministisk port

Kall Verify(repo.Path). Når StopOnVerifyFailure er sann, skal en rød sjekk stoppe leveransen før PR-en opprettes.

var (verified, verifyLog) = await Verify(repo.Path);
if (!verified && config.StopOnVerifyFailure)
{
    await Kommenter(repo, task, Fence(verifyLog, 2000));
    return 2;
}

Sjekk: dotnet build.

7

Leveranse · reviewbar PR

Commit, push og opprett pull request

Lever branchen med CommitAndPush, opprett PR med CreatePullRequest, og bruk utkast når verifiseringen er rød.

await repo.CommitAndPush(
    task.BranchName, $"{task.Title}\n\nLøser #{task.IssueNumber}.");
var prUrl = await repo.CreatePullRequest(
    task.BranchName, task.Title,
    PrBody(task, previousOutput, verified, verifyLog, runs),
    draft: !verified);

Sjekk: dotnet build. Agenten leverer et forslag; den godkjenner ikke sitt eget arbeid.

Kjør og nå sjekkpunktet

dotnet run --project src/Worker -- `
  --issue 1 `
  --repo novanet/workshop.oslo-live `
      --force

På macOS/Linux kan du bruke \ i stedet for PowerShells linjefortsettelse. Følg loggen: oppgaven hentes, repoet klones, modellen kjører, bygg/test kjøres og PR-adressen skrives ut.

Sjekkpunkt 1Du har selv montert pipelinen, PR-en er opprettet, og du kan peke på hva som er deterministisk kode og hvor modellen brukes.

Hvis du faller av

Ta vare på forsøket og legg inn den ferdige Lab 1-pipelinen:

./sjekkpunkt.sh lab1
dotnet build

I PowerShell:

Copy-Item src\Worker\Pipeline.cs .kurs\Pipeline.forsok.cs
Copy-Item .kurs\checkpoints\lab1\Pipeline.cs src\Worker\Pipeline.cs
dotnet build
Ikke skjul feilenLes gjerne diffen i forsøket ditt etterpå. Sjekkpunktet er et redningsnett, ikke en erstatning for å forstå rekkefølgen.

Vil du bli tidlig ferdig?

  • Bytt modell i agent/stages.json og sammenlign kvalitet og kostnad.
  • Reduser maxTurns og se når agenten ikke rekker oppgaven.
  • Fjern mcp__allemannsdata fra allowedTools og se hva som endrer seg.
  • Sett stopOnVerifyFailure til true og kjør en oppgave som feiler.
